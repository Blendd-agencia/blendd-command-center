# Editorial templates, memory and generation

The client backoffice exposes Templates e memória. Resources live under each client's `social.ruleResources[ruleId]`; the same structure handles the free-content rule. Templates keep a version, private PNG/JPEG preview, optional PDF reference, editable-source URL, dimensions/format, slide count and written layout limits. Binary assets reuse the existing private upload path and quotas. Backup reference validation includes these assets.

Feedback remains on its source post. An administrator may explicitly promote it to an active rule for that rubric; unconfirmed entries stay inactive. Edits retain the previous text/status. General briefing sections and only the selected rubric's instructions, active rules, chosen template and associated materials enter the prompt. Unknown briefing sections are excluded unless marked `aiScope: general`. The initial Tec Labs general sections are position, channels and visual; no combined all-rubric summary is sent.

POST /api/editorial-ai authenticates an administrator, checks origin and workspace revision, reads the authoritative client/post/materials and reserves a durable operation before invoking AI Gateway. The server uses the current Vercel OIDC request header, or a server-only AI_GATEWAY_API_KEY. Model fixed to openai/gpt-4.1, verified in the gateway model catalog on 2026-11-10. No public credentials, link fetching, tools or automatic posting. PNG/JPEG previews use low-detail visual input; exact typography/layout constraints should be written in the template instructions.

Initial test limits: 3 new requests per minute, 20 per UTC calendar month across the application. Input context at most 30,000 characters, one preview <=3MB, output <=3500 tokens, provider timeout 25s. A conservative USD 0.25 allowance per request is displayed (USD 5 total at 20 requests); it is not actual invoiced spend. Failed/interrupted operations count conservatively. Limits are atomic in Postgres. A repeated operation ID cannot trigger another model request. Results, errors, token usage and brief/rule/template/memory provenance are stored in cc_ai_jobs with RLS; direct inserts/updates are not granted to authenticated users. No automatic provider retries.

The proposal must be explicitly applied. Client-owned text is preserved, existing post changes block applying an in-flight response, and applying team-owned text invalidates prior approvals. Existing jobs can be reviewed in history. Conflicting server writes retain the existing workspace conflict protection.

This phase generates copy and slide text, not rendered artwork. PDF/editable links are references for humans and are not parsed or filled. Raw materials need text; links alone do not count as readable input for AI. Final artwork rendering requires choosing an editor/rendering integration after the real templates are supplied.

Verification: unit/API tests mock the paid provider; database reservation/idempotency tests run with rollback. A successful deployment is not proof of available AI Gateway credit/access. The first authenticated real generation remains the live connectivity and editorial-quality test. No real customer post was generated or overwritten during setup.
